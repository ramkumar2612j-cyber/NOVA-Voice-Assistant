## 3. WHAT PART 1 CHANGED (all add-only)
- NEW app/src/main/java/com/nova/assistant/AutoIntent.kt: pure Kotlin object. detect(text, hasPhoto) -> Result(kind SITE|IMAGE|PHOTO_EDIT|NONE, subject, blocked, why). Understands free wording: "mujhe ek logo chahiye", "i need a poster for my cafe", "gym ke liye site chahiye", "ek billi draw karo", "online store banwana hai". Order rule: English verb in first 3 tokens = object is the first noun AFTER the verb; Hindi order = nearest noun BEFORE the verb ("website ke liye logo banao" = IMAGE, "logo wali website banao" = SITE). "bina photo ke website" = SITE; component words (sath/with/wali/aur) make a picture word part of a site. Question words (kaise, how, kyu, matlab, explain...) = NONE. OTHER set (kholo, send, share, whatsapp, gallery, camera, edit, publish, music, alarm...) = NONE so other features keep their sentences. Blocked words flagged (images) + SiteIntent.isBlocked (sites). Subject for images goes through ImageIntent.parse (billi -> cat).
- NovaService.process: right AFTER the old `imgReq` route (so SiteIntent / MediaIntent / ImageIntent stay first) a new `autoReq` block calls siteBegin / imageBegin. PHOTO_EDIT is not routed in Kotlin (needs the picked photo in MainActivity; Part 2 does it from the UI via editPhoto).
- MainActivity: new bridge `detectIntent(text, hasPhoto): String` JSON {kind, subject, blocked, why} (read-only, starts nothing), placed before the chat-sessions block.
- ui.html (appended before </body>): <style id=p1_auto_css> hides #c_imode (code kept) and styles the chip #c_auto; <script id=p1_auto>: live chip "NOVA SAMJHA: WEBSITE / PHOTO-IMAGE BANANI HAI / PHOTO EDIT" while typing (250 ms debounce, calls Android.detectIntent), a document-level capture handler that turns the old IMAGE switch OFF before a send when no photo is attached (so the hidden switch can never get stuck ON), and the X (remove photo) button also resets it. (Helper is named byId, not g(), because tools/test_photo_publish_contract.py forbids g('literal') in new JS.)
